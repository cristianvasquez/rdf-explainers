rdf-cli · rdf claim · @rdf-viz/claimer-runtime

Claimers take shapes of data off the wire and draw them.

A claimer is one SHACL claim plus one or more CONSTRUCT views. The claim takes the triples its shapes read. The view projects them into new RDF for a viewer. Several claimers run as a Unix pipe, and the pipe order is the precedence.

rdf read data.ttl \ | rdf claim person.trig \ | rdf claim organization.trig \ | rdf claim place.trig \ | rdf pretty --format trig

Wire log

    What one claim guarantees

    Four laws, no runtime checks

    claimed ∪ rest = input

    Partition. Every graphless quad is owned by this claimer or stays in the rest.

    claimed ∩ rest = ∅

    Disjoint. An owned quad leaves graphless space. A later claimer cannot read it.

    frontier ⊆ rest

    Borrowed quads feed the views and stay on the wire. Only a copy goes to the frontier graph.

    views commute

    Every view of one claimer reads the same feed: source ∪ frontier. No view reads the output of another view.

    Input of the animation

    The data and the three claimer documents

    One TriG document defines one claimer: one named graph with the shapes and the views. The subject of cascade:query names the graph where the view output goes. The viz: drawing vocabulary is invented for this explainer.

    
  
    

    


    
  
    Where the animation simplifies.
    
  
    The hose moves quads one at a time. rdf claim does not decide per quad: it collects the graphless working set, runs the SHACL claim on the whole set, then splits it. The animation shows the result of that split, quad by quad.
    
  
    On the real wire, owned quads and view output continue downstream as named quads, and later claimers pass them through untouched. The animation lifts them out of the hose to show the graph where each one lands.
    
  
    The claim logic in this page is a small copy of the rules (owned = constraint paths of target nodes, frontier = rdf:type of sh:targetClass). It does not run SHACL validation, so sh:minCount has no effect here.
